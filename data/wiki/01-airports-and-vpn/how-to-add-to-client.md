## NodeNanny 的订阅地址在哪里

打开 NodeNanny 面板首页，找到"订阅地址"一栏，格式类似：

```
http://你的服务器IP:35319/sub?token=xxxxxxxx
```

这个地址是 NodeNanny 自动生成的"智能订阅"——自建节点正常时返回你的真实节点，
自建节点出问题时自动切换成备用池里的节点，不需要你手动换链接。

**注意**：35319 是订阅专用端口，无需登录验证；49769 是面板管理端口，带密码保护。
两个端口用途不同，不要混淆。

**订阅地址里含有 token，请不要把这个链接分享给他人**——拿到链接的人可以直接拉取你的节点列表，无需任何登录。

## 各客户端导入方法

### Clash Verge（Windows / macOS / Linux，推荐）

1. 打开 Clash Verge，左侧点击**"订阅"**（Profiles）
2. 点右上角的**"新建"**按钮
3. 类型选**"远程"**（Remote）
4. 在 URL 栏粘贴 NodeNanny 的订阅地址
5. 点**"导入"**，等待拉取完成
6. 点击刚导入的配置右侧的**"使用"**按钮激活它

导入后建议在"订阅"页面里对这条记录开启**自动更新**（设置更新间隔为 1~6 小时），
这样当 NodeNanny 的备用池发生变化时，客户端能及时同步。

Clash Verge 内置延迟测试功能：在订阅配置里右键，可以对当前所有节点批量测速，选延迟低的节点使用。

### Shadowrocket（iOS）

1. 打开 Shadowrocket，点右上角**"+"**
2. 类型选**"Subscribe"**（订阅）
3. URL 填入 NodeNanny 的订阅地址
4. 备注随便填，保存
5. 回到首页，点那条订阅右侧的**刷新图标**拉取节点
6. 在节点列表里选一个节点，打开右上角的连接开关

**注意**：Shadowrocket 导入后默认不会自动更新，需要手动下拉刷新，或者在
"配置"→"订阅"里设置自动更新间隔。

批量测速：在首页节点列表里，点右上角的测速图标，可以对所有节点测延迟。

### v2rayN（Windows）

1. 打开 v2rayN，顶部菜单点**"订阅分组"**→**"订阅分组设置"**
2. 点**"添加"**，在 URL 栏填入 NodeNanny 的订阅地址，备注随便填
3. 确定保存后，回到主界面，点顶部菜单**"订阅分组"**→**"更新全部订阅（通过代理）"**
4. 等待右下角状态栏显示更新完成，节点列表里会出现新节点
5. 双击一个节点使其变成"激活"状态，然后在系统托盘右键选择代理模式

批量测速：主界面选中节点后，右键菜单里有"测试服务器延迟（all）"选项。

### sing-box 系客户端（如 NekoBox、Hiddify 等）

这类客户端对订阅格式的支持因版本而异。NodeNanny 生成的订阅内容是标准的
Base64 编码节点列表（兼容 Clash/v2ray 通用格式），大多数现代客户端都能识别。

导入方式通常是：主界面→订阅/配置→新增→粘贴 URL→更新。

如果导入后显示"0 个节点"或解析失败，说明这个客户端对格式有特殊要求，
可以尝试在订阅 URL 末尾加上 `&flag=clash` 参数（即 `...&token=xxx&flag=clash`）
让 NodeNanny 返回 Clash YAML 格式的内容。支持的 flag 值以面板首页订阅区的说明为准。

## 常见问题

**Q：导入之后节点列表是空的**

最可能的原因是 NodeNanny 这一轮还没有可用节点（来源都在试用期或刚启动），
等 6 小时后再刷新一次试试。也可以去面板的节点池区域看看当前实际有多少节点。

**Q：节点都连不上，全部超时**

NodeNanny 备用池里的节点是从公开频道收集来的，质量参差不齐——通过率检测只
确认节点"能连通"，不保证速度或稳定性。遇到这种情况，在客户端里批量测速（各客户端测速方法见上方各章节），选延迟低的节点用。如果测速后仍然全部超时，说明备用池这一轮整体质量较差，等下一轮刷新（6 小时）再试。

**Q：客户端显示"无法解析订阅"**

确认你复制的订阅地址完整，没有漏掉 `?token=` 后面的部分。同时确认服务器的
35319 端口没有被防火墙拦截（参考故障排查：面板打不开里关于防火墙的说明）。
