## 适用环境

安装脚本目前支持 Ubuntu 20.04/22.04/24.04 和 Debian 11/12。建议用一台全新的 VPS，
避免跟已有服务冲突。

## 安装做了什么事

执行安装脚本时，会依次经过几个阶段：

1. **选择语言** —— 目前支持中/英/日/德/俄五种，装完之后终端里看到的提示、面板界面
   都会跟着这个选择走
2. **检查依赖** —— 确认服务器上的 Node.js 版本达标，缺什么会提示怎么装
3. **安装底层代理程序** —— 这一步会调用业内常用的一键装机脚本来安装真正干活的代理
   服务本身（xray/sing-box），NodeNanny 不重新发明这部分，只负责"看住它"
4. **写入配置** —— 生成 `config/config.json`，包括面板密码、绑定地址这些
5. **用 PM2 启动三个常驻进程** —— `nodenanny-monitor`（存活监控）、`nodenanny-panel`
   （网页面板）、`nodenanny-pool`（备用节点池维护）

## 关于断线

如果是通过 SSH 远程操作服务器，安装过程中网络抖动导致连接断开，安装脚本本身设计
成不会因此被杀死——但更稳妥的做法还是先在服务器上开一个 `tmux` 或 `screen` 会话
再执行安装脚本，这样断线重连后可以 `tmux attach` 回去接着看进度，体验更完整。

## 装完之后怎么打开面板

面板默认只监听本机地址（`127.0.0.1`），也就是说默认情况下你没法直接在浏览器里用
服务器公网 IP 打开它——这是刻意的安全设计，避免面板一装完就暴露在公网上。有两种
常见打开方式：

- **SSH 隧道**：本地执行 `ssh -L 本地端口:127.0.0.1:面板端口 你的服务器`，然后浏览器
  打开 `http://127.0.0.1:本地端口`
- **配 Nginx 反代 + 密码**：如果你想直接用域名/公网 IP 访问，需要在配置里显式设置
  面板密码，并按 `deploy/nginx-nodenanny.conf.example` 这个示例配置文件配好反向代理。
  面板检测到你把绑定地址改成非本机、但密码还是空的，会直接拒绝启动，这是防止"忘记
  设密码就暴露在公网"的保护措施，不是bug。

## 装完第一件事：确认三个进程都在跑

```bash
pm2 status
```

应该能看到 `nodenanny-monitor`、`nodenanny-panel`、`nodenanny-pool` 三个进程都是
`online` 状态。如果某个进程反复重启或者是 `errored`，用 `pm2 logs 进程名` 看具体报错，
这个也是"节点/代理协议行业通识"和这里都会陆续收录的常见故障排查起点。
