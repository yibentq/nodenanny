## 这篇教程是做什么的

NodeNanny 的应急流量池（pool）默认会自动从公开渠道发现一些备用节点源，但你也可以手动指定自己信任的节点源——比如你自己长期在用的某个 GitHub 订阅仓库，或者某个 Telegram 频道分享的订阅链接。手动添加的节点源默认会被标记为"固定可信"，不需要像自动发现的来源那样，从 trial（观察期）一步步跑到 trusted（正式可信）才能用满权重。

## 配置在哪里

打开 `config/config.json`（不是 `config.example.json`，那个只是模板），找到 `manualSources` 这个数组，里面已经有一个例子：

```json
{
  "id": "wangcai",
  "name": "旺财",
  "url": "https://shz.al/~WangCai",
  "fixed": true
}
```

四个字段的意思：
- `id`：这个节点源的唯一标识，自己起一个英文/拼音的短名字就行，不能跟已有的重复
- `name`：显示在面板上的名字，可以用中文
- `url`：订阅链接地址
- `fixed`：设成 `true`，表示这个来源直接享受"固定可信"待遇，不用走信任评估流程。这一项也可以不写（默认就是走正常的信任评估流程，跟自动发现的来源一样对待）——具体选哪种看你自己有多信任这个来源。

## 添加一个新来源，具体步骤

1. 找到你想加的订阅链接（GitHub 上某个仓库的 raw 链接，或者别人分享的订阅地址）
2. 在 `manualSources` 数组里，参考 `wangcai` 这一条的格式，加一条新的，比如：

```json
{
  "id": "my-source-1",
  "name": "我自己的备用订阅",
  "url": "在这里粘贴订阅链接",
  "fixed": true
}
```

记得前一条记录后面要加逗号，JSON 格式对逗号和括号比较敏感，改完建议找个在线 JSON 校验工具粘贴进去看一眼格式对不对，避免因为少个逗号导致整个配置文件读取失败。

3. 保存文件
4. 重启 `nodenanny-pool` 这个 PM2 进程，让新配置生效：

```
pm2 restart nodenanny-pool
```

5. 在面板里查看流量池状态，确认新加的这个来源已经出现，并且能正常抓到节点

也可以不手动编辑配置文件——如果你想加的来源已经在官方维护的候选来源列表里，面板设置里的"检查更新"功能能直接对比出你本地缺的来源，点一下确认合并即可，不用自己写 JSON。手动编辑配置文件这条路适合添加候选列表里没有的、你自己发现的来源。

## 关于 Telegram 频道来源

如果你想加的是一个 Telegram 频道，目前支持两种消息里带订阅链接的形式：直接以文本形式贴出的链接，以及包在代码块里的链接（比如用反引号包起来的那种格式），这两种都能被正确提取出来。"频道里发的文件附件"这种形式目前是不可用的（Telegram 的公开预览页面不会给出文件的真实下载地址，只会给一个跳转链接，技术上拿不到）。所以加 Telegram 频道源的时候，先确认一下这个频道分享订阅的方式是发文本/代码块形式的链接，而不是发文件。

还有一点值得知道：Telegram 频道来源的信任状态，实际追踪的不是"这个频道"本身，而是频道里解析出来的订阅链接背后的域名。同一个频道换了个订阅域名，会被当成一条新的来源重新观察；反过来，只要域名没变，即使某一轮频道消息暂时抓取失败（比如频道当天没发新链接），也不会因此影响这个来源已经积累的信任状态——这是有意的设计，为的是让"频道本身能不能连上"和"频道产出的订阅链接质量如何"这两件事分开评估，互不干扰。

## 关于"是否要设成 fixed: true"

`fixed: true` 意味着这个来源不用经过信任评估、直接享受满权重，适合你已经长期验证过、确实信得过的来源（比如自己维护的仓库）。如果是刚发现的、还不确定质量如何的来源，建议不加 `fixed` 字段，让它跟自动发现的来源一样，走正常的观察期评估流程，这样即使这个来源质量不稳定，也不会一上来就占用很高的权重——具体信任机制是怎么运作的，可以看《节点池信任机制是怎么运作的》这篇。
