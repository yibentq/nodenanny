## 面板首页看什么

- **自建节点状态**：你自己的代理服务是否存活，配合底部的存活时长统计
- **订阅地址**：NodeNanny 自己会生成一个"智能订阅"链接，客户端订阅这一个地址就够——
  自建节点正常时返回真实节点，自建节点异常且备用池里有可用节点时自动切换成备用
  节点内容，不需要你手动切换订阅链接
- **备用节点池 / 星图视图**：备用池里当前有哪些来源、每个来源的信任状态（试用中/
  已信任/已拉黑）、节点数量
- **备用池手动切换开关**：正常情况下，是否使用备用池是全自动判断的（自建节点异常
  才会切）。如果你想不管自建节点状态如何、强制先用备用池（比如你确定自建节点这段
  时间会不稳定），可以手动打开这个开关，界面上会有明显的提示（灯塔图标点亮+
  横幅文案）告诉你当前处于"手动覆盖"状态，此时系统不会自动把它切回去，需要你
  自己手动关闭这个开关才会恢复自动判断。

## 手动加一条你自己信任的订阅源

如果你自己有稳定的订阅链接（不管是自己另外买的机场，还是朋友分享的），想让它也
参与备用池，走的是"手动来源"这条路径，新加的来源同样要经过试用期考察，不会因为
是手动加的就跳过信任分级（除非你显式设置 `fixed: true`，具体见《如何手动添加一个
节点源》）。有两种添加方式：

**方式一：面板里的"官方候选源同步"**（如果你想加的来源已经在官方维护的候选列表里）
面板设置里有一个同步入口，点击"检查更新"会跟官方维护的候选来源列表做一次对比，
列出你本地还没有的新来源，你确认要不要合并进来。这种方式不用自己手写 JSON，适合
候选列表里已经有你想要的来源的情况。

**方式二：手动编辑配置文件**（适合添加候选列表里没有的、你自己发现的来源）

```bash
cat <<'EOF' | node
const fs = require('fs');
const config = JSON.parse(fs.readFileSync('config/config.json', 'utf-8'));
const newSources = [
  { id: '给这条源起个短标识', name: '显示名称', url: '订阅链接' }
];
for (const s of newSources) {
  if (!config.pool.manualSources.some(x => x.id === s.id)) {
    config.pool.manualSources.push(s);
  }
}
fs.writeFileSync('config/config.json', JSON.stringify(config, null, 2));
console.log('写入完成:', config.pool.manualSources.map(s => s.id));
EOF
pm2 restart nodenanny-pool
```

用 heredoc 写 JS 脚本而不是直接用 `sed`/`echo` 拼接 JSON，是为了避免手动改 JSON
容易漏逗号/多逗号导致整个配置文件解析失败；这个写法在项目里已经反复验证过没问题。

加进去之后，这条来源会先以"试用"状态运行一段时间，面板星图视图上能看到它的实时
通过率，不需要额外操作。

## 在线终端

面板里有一个"在线终端"功能，解锁后可以直接在浏览器里对服务器执行命令，不需要
另外开 SSH 连接。几个要知道的点：

- 解锁在线终端需要单独的终端密码（安装时设置的那个，跟面板登录密码是两把不同的锁）
- 终端有独立的会话时长，超时会自动锁定，需要重新输入密码解锁
- 执行一些高风险命令（比如涉及删除、重启服务这类）时，终端会要求你二次确认才会
  真正执行，不是输入即执行——这一步是刻意的摩擦设计，避免手滑
- 连续几次密码输错会触发短暂锁定，防止被暴力破解密码

这个功能主要是给"服务器出了问题、但你人不在电脑前、或者懒得开专门的 SSH 客户端"
这种场景准备的应急入口，日常操作优先还是用面板本身的功能。

## AI 辅助诊断

如果安装时配置了 AI 服务商（或者之后在设置里补配置的），面板会有一个 AI 辅助诊断
入口。触发之后，它会结合当前的节点状态、最近的异常日志，给出一段用大白话解释的
诊断建议——定位是"帮你看懂发生了什么、可能是哪里的问题"，不是自动帮你操作或者
自动修复。如果没配置 AI 服务商，这个入口不会出现，不影响其他功能正常使用。

## 什么时候该去看"节点/代理协议行业通识"这个分类

如果你发现某类节点（比如某个协议）测试通过率一直很低，但你确认订阅源本身没问题，
大概率是协议层面的知识盲区，而不是 NodeNanny 配置错了——这种情况建议去"节点/代理
协议行业通识"分类里查一下对应协议的说明，那边讲的是协议本身的原理和常见限制，
不是 NodeNanny 这个工具的用法。
