## パネルのトップページで見られるもの

- **自前ノードの状態**:自分のプロキシサービスが生きているかどうか、下部には稼働時間の
  統計も表示されます
- **サブスクリプションアドレス**:NodeNanny は独自に「スマートサブスクリプション」リンク
  を生成します。クライアントはこのアドレス1つを購読するだけで十分です——自前ノードが
  正常なときは本物のノードを返し、自前ノードに異常があり予備プールに使えるノードがある
  ときは自動で予備ノードの内容に切り替わります。サブスクリプションリンクを手動で切り
  替える必要はありません
- **予備ノードプール/星図ビュー**:予備プールに現在どんな情報源があるか、各情報源の信頼
  状態(試用中/信頼済み/ブラックリスト入り)、ノード数

## 自分が信頼するサブスクリプションソースを手動で追加する

もしあなた自身に安定したサブスクリプションリンクがある場合(別途契約している機場でも、
友人から共有されたものでも)、それも予備プールに参加させたいときは「手動ソース」という
経路を使います。手動で追加した情報源も同じ試用期間の審査を経る必要があり、手動追加だから
といって信頼度ランクをスキップすることはありません:

```bash
cat <<'EOF' | node
const fs = require('fs');
const config = JSON.parse(fs.readFileSync('config/config.json', 'utf-8'));
const newSources = [
  { id: 'このソースの短い識別子', name: '表示名', url: 'サブスクリプションリンク' }
];
for (const s of newSources) {
  if (!config.pool.manualSources.some(x => x.id === s.id)) {
    config.pool.manualSources.push(s);
  }
}
fs.writeFileSync('config/config.json', JSON.stringify(config, null, 2));
console.log('書き込み完了:', config.pool.manualSources.map(s => s.id));
EOF
pm2 restart nodenanny-pool
```

`sed`/`echo` でJSONを直接組み立てるのではなく heredoc でJSスクリプトを実行する理由は、
JSONを手動で編集するとカンマの抜けや余分なカンマによって設定ファイル全体の解析が失敗
しやすくなるのを避けるためです。このやり方はプロジェクト内で繰り返し検証済みで問題あり
ません。

追加すると、この情報源はしばらく「試用」状態で動作し、パネルの星図ビューでリアルタイムの
合格率を確認できます。追加の操作は必要ありません。

## 「ネットワーク・プロトコル業界の基礎知識」カテゴリを見るべきタイミング

あるタイプのノード(例えば特定のプロトコル)のテスト合格率がずっと低いのに、サブスクリ
プションソース自体には問題がないと確認できた場合、それはたいてい NodeNanny の設定ミス
ではなく、プロトコルに関する知識の空白であることが多いです——このような場合は「ネット
ワーク・プロトコル業界の基礎知識」カテゴリで該当プロトコルの説明を確認することをおすすめ
します。そちらではプロトコル自体の仕組みや一般的な制限について解説しており、NodeNanny
というツールの使い方については扱っていません。
