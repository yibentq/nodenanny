## Что видно на главной странице панели

- **Статус собственного узла**: жив ли ваш прокси-сервис, вместе со
  статистикой времени безотказной работы внизу
- **Адрес подписки**: NodeNanny сам генерирует ссылку «умной подписки» —
  клиенту достаточно подписаться на этот единственный адрес: когда
  собственный узел в порядке, возвращаются настоящие узлы, а когда
  собственный узел неисправен и в резервном пуле есть рабочие узлы,
  происходит автоматическое переключение на резервное содержимое без
  необходимости вручную менять ссылку подписки
- **Резервный пул узлов / вид звёздной карты**: какие источники сейчас в
  резервном пуле, статус доверия каждого источника (испытательный срок/
  доверенный/заблокирован), количество узлов

## Ручное добавление собственного доверенного источника подписки

Если у вас есть собственная стабильная ссылка на подписку (будь то
отдельно купленный аэропорт или ссылка, которой поделился друг), и вы
хотите, чтобы она тоже участвовала в резервном пуле, используется путь
«ручных источников» — вновь добавленный источник точно так же проходит
испытательный срок, а не пропускает уровни доверия только потому, что
добавлен вручную:

```bash
cat <<'EOF' | node
const fs = require('fs');
const config = JSON.parse(fs.readFileSync('config/config.json', 'utf-8'));
const newSources = [
  { id: 'краткий идентификатор источника', name: 'отображаемое имя', url: 'ссылка на подписку' }
];
for (const s of newSources) {
  if (!config.pool.manualSources.some(x => x.id === s.id)) {
    config.pool.manualSources.push(s);
  }
}
fs.writeFileSync('config/config.json', JSON.stringify(config, null, 2));
console.log('Записано:', config.pool.manualSources.map(s => s.id));
EOF
pm2 restart nodenanny-pool
```

Использование heredoc с JS-скриптом вместо склейки JSON через `sed`/`echo`
нужно, чтобы избежать ситуации, когда при ручном редактировании JSON легко
пропустить запятую или добавить лишнюю, из-за чего весь конфигурационный
файл перестанет парситься; этот подход в проекте уже неоднократно
проверен и работает без проблем.

После добавления источник сначала некоторое время работает в статусе
«испытательный срок»; его реальный процент успешности виден в режиме
звёздной карты на панели, дополнительных действий не требуется.

## Когда стоит заглянуть в «Общие знания о сетях и протоколах»

Если вы заметили, что определённый тип узлов (например, узлы с
определённым протоколом) стабильно проходят проверку с низким процентом
успеха, но при этом сам источник подписки в порядке — скорее всего, это
пробел в знаниях на уровне протокола, а не ошибка конфигурации NodeNanny.
В таком случае стоит заглянуть в раздел «Общие знания о сетях и
протоколах» и посмотреть объяснение по соответствующему протоколу — там
речь идёт о принципах работы и типичных ограничениях самого протокола, а
не об использовании инструмента NodeNanny.
